# Практика — статическая версия для GitHub Pages

Сборка и сервер не требуются. Вопросы и ключи взяты из двух предоставленных PDF. Файлы используют относительные пути и работают как в корне домена, так и по адресу /имя-репозитория/.

## Публикация

1. Распакуйте архив и загрузите его содержимое в корень вашего репозитория GitHub: index.html должен лежать непосредственно в корне, а не внутри дополнительной папки.
2. Откройте Settings → Pages → Build and deployment → Source → Deploy from a branch.
3. Выберите ветку main (или ветку, в которую загрузили файлы), папку /(root) и нажмите Save.
4. Дождитесь публикации. Адрес сайта появится на странице Settings → Pages.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Возможности

- Настройка количества вопросов каждого типа, включая 0 для исключения типа.
- Кнопка «Показать ответ» / «Скрыть ответ» на каждом вопросе. Просмотр не выбирает ответ автоматически и не меняет оценку.
- Разбор после завершения: ваш выбор, правильные ответы, ошибки и пропуски. Можно раскрыть все вопросы сразу.
- История, продолжение незавершённых тестов и прогресс по типам.

## Хранение истории

Данные сохраняются в IndexedDB этого браузера на этом устройстве. Сервер и учётная запись не используются; между устройствами история не синхронизируется. Локальная сетевая версия продолжает использовать общую историю на компьютере.

Очистка данных сайта удалит историю. В приватном режиме браузер может удалить её при закрытии окна. Смена домена или пути сайта создаёт отдельное хранилище. История из локальной сетевой версии не включена в этот архив.

Загружайте весь комплект файлов. Не подключайте static-storage.js к серверной версии, если хотите сохранить общую историю локальной сети.
